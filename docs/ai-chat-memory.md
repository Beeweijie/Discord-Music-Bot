# DeepSeek 群聊与记忆

这版以 Discord 文字群聊作为测试入口。机器人可以先观察，再像群友一样决定是否接话。
音乐、语音点歌、欢迎、投票、托盘和自动更新继续通过各自的 feature 工作。

## 启用测试频道

1. 在机器人实际使用的 Python 环境安装 `requirements.txt`。这次新增 `tzdata`，
   供 Windows 正确处理频道时区和安静时段；不需要安装完整 AI 框架或向量数据库。
2. 在本地已有 `.env` 增加 `DEEPSEEK_API_KEY=你的密钥`。默认地址是
   `https://api.deepseek.com`；不要把密钥放进人设、频道消息或网页配置。
3. 在 Discord Developer Portal → Bot 中启用 **Message Content Intent**，
   并保留 `MESSAGE_CONTENT_ENABLED=true`。机器人要能查看和发言。
4. 正常启动 `python main.py`，打开 `http://127.0.0.1:8766/#chat`。
   选择服务器、启用群聊、勾选测试频道，先保存为 **Observe**。
5. 群内正常聊天后点 Refresh 查看决策。确认接话频率与人设合适，再把该频道改为
   **Participate**。也可由有 Manage Server 权限的成员在频道使用 `/chat observe`
   或 `/chat on`；`/chat off` 只停止当前频道，`/chat status` 查看状态。
6. 如需跨重启保留事实，进入 `#memory`，单独启用 Memory。频道仍须在群聊允许列表内。
   不启用长期记忆时，当前进程内的短期上下文照常使用。

默认模型是当前 DeepSeek API 的 `deepseek-flash`，在网页 Advanced 中可分别配置
群聊和记忆抽取模型。群聊默认按需选择思考模式；判断、记忆抽取与后台冲浪使用快速模式。
输出均有上限，接口失败不会自动无限重试。
当前接口参数依据 [DeepSeek 文档](https://api-docs.deepseek.com/api/create-chat-completion/)。
修改 `.env` 后需要重启；网页中的服务器配置用于后续操作并在发送前重新核验。

## 群友式接话

普通消息先通过本地筛选和合并，再判断 `reply / wait / skip`。问句不等于必须回答。
模型会参考聊天对象、近期消息、人设兴趣、记忆与最近发言间隔。直接 @、回复机器人，
或以配置的别名开头，会进入直接回应流程；直接回应仍受成员频率和模型调用预算约束。
@ 对象按 Discord 用户 ID 区分。只 @ 其他成员或机器人的消息会在本地跳过，
不会把别人的昵称或点名当成在叫自己；模型上下文也会包含本机器人的真实 ID。

默认参数：

| 项目 | 默认值 | 作用 |
|---|---|---|
| 群聊 / 长期记忆 | 均关闭 | 必须显式启用 |
| 模式 | Observe | 只记录判断；不生成或发送回复 |
| 普通消息合并 / 最长等待 | 5 秒 / 15 秒 | 避免每条消息都调用模型 |
| 自主接话冷却 | 90 秒 | 直接呼叫可绕过 |
| 自主发送额度 | 每小时 10 次 | 防刷屏；每日条数默认不限制 |
| AI 每日预算 | ¥1 | 全实例所有 AI 功能合计，Sydney 零点重置 |
| 直接呼叫 | 每成员每频道 30 秒内最多 3 轮 | 避免连续刷请求 |
| 上下文上限 | 50 条 / 16,000 个原文字符 | 达上限时成批缩小窗口 |
| 日常回复上限 | 300 token / 600 字符 | 通常一到三句；可自然拆成最多三条 |
| 默认时区 | Australia/Sydney | 可以修改 |
| 安静时段 | 空 | 可设置如 23:00-08:00，仅约束自主接话 |

不同频道可覆盖参与模式、人设、兴趣和自主冷却/额度。网页目前直接提供频道模式覆盖；
其他允许的覆盖字段由配置 schema 支持。被排除的成员按 ID 处理，不按昵称匹配。

有新消息、权限变化、设置变化、源消息编辑/删除或记忆失效时，旧回复会取消。
发送结果不明确时记录为 unknown，不盲目补发。机器人不会跟其他机器人互聊，
不会读取私信，不会把模型生成的文字当成音乐控制命令。

## 缓存的设计与观察

DeepSeek 的前缀缓存默认启用，但命中是服务端尽力提供的结果。相同文字出现在请求中间，
并不意味着一定命中；完整前缀、服务端持久化和缓存淘汰都会影响结果。
当前规则与限制见 [官方缓存说明](https://api-docs.deepseek.com/guides/kv_cache/)。

这里采用：

1. 判断使用独立的极简固定前缀、薄人设和几条压缩消息，目标约 300 输入 token；
   回复使用完整人设与历史，各自观察缓存命中，不为共享前缀而给判断加载整段历史。
2. 回复的当前时间、发言间隔、本轮检索记忆、任务说明放在最后，减少前部变化。
3. 回复历史逐条追加，到数量或字符上限后收缩到约 75%，再继续增长。
   超长单条消息本身也会截断；编辑、删除、排除成员及人设变化会自然使前缀变化。
4. 从 API 的 usage 保存 `prompt_cache_hit_tokens`、`prompt_cache_miss_tokens`、
   输出 token，以及模型、阶段和请求状态。旧账本会添加统计列，保留已有记录。
5. 网页按实际已上报的输入 token 计算命中率，并标出上报请求数量。
   提供商没上报时显示未知；不会假设高命中率。

判断与回复的输入已分离；不能假定二者共享缓存，也不以高命中率替代减少不必要的输入。
当前实现也没有花钱预热缓存。真实命中率、延迟和成本要用测试频道的数据测量。

计算费用应分别使用「命中输入 × 命中价 + 未命中输入 × 未命中价 + 输出 × 输出价」，
并按模型与当期计费时段核对 [官方价格](https://api-docs.deepseek.com/quick_start/pricing/)。
预算使用 2026-10-31 核对的官方高峰单价保守核算；费率集中在 `shared/llm/pricing.py`，
需随官方调价维护。缓存降低推理成本；长期记忆仍由本地
数据库负责，不能依靠服务端缓存保证重启恢复或永久记住事实。

`DEEPSEEK_DAILY_BUDGET_CNY=1` 为全实例金额上限；`DEEPSEEK_BUDGET_TIMEZONE=Australia/Sydney`
决定零点重置时间。判断、回复、搜索、抓取、识图、记忆与人设复盘/审核全部共用账本。
请求前在 SQLite 事务中预留费用，包含正在进行的调用，重启不会丢失预留。文本按 UTF-8
字节上界、图片按每张 1024 token 上界、输出按 max_tokens 预留，收到 usage 后按缓存
命中/未命中分别结算。Search/Fetch 每次有结果的成功请求按 ¥0.005 计算；明确失败/空
结果不扣这笔费用。超时、崩溃或缺 usage 的请求保留保守费用，不冒险退还未知账单。
高峰价会高估空闲时段实际消费；临近上限时也可能因无法预留完整一轮而提前停用。
这控制本实例的调用，不包含同一 Key 被其他程序使用的费用。平台账单仍以平台为准。

`DEEPSEEK_DAILY_REQUEST_LIMIT` / `DEEPSEEK_DAILY_TOKEN_LIMIT` 和频道每日计数上限均可
设为 0（默认）只按金额控制。旧配置中的非零上限会保留，切换预算制时可手动改为 0。

## 记忆如何形成

允许频道的真人消息先保留为带 ID 和修订号的来源。默认每 30 条或等待 300 秒产生一批；
“记住”“更正”等表达可提前排队。后台抽取事实、事件和该批摘要，再在同一事务中核验：

- 来源确实存在于这个频道、修订号一致、未被删除或忘记。
- 个人事实的主体必须对应来源里的本人 ID；第三方转述或不确定内容不自动作为事实召回。
- Observe 期间产生的是候选，必须在网页批准后才参与召回。
- 独立偏好可以并存，明确的排他更正或活动改期才替代同槽位记录。
- 日期依据消息时间与频道时区解释；计划不会被当作已经完成的经历。
- 固定凭据格式由本地筛选拦截；抽取仍是模型判断，需要人工检查准确性。

默认保留原文 30 天，召回最多 6 条，抽取同样受共享金额预算约束。

## 深浅记忆与两阶段回复

浅层用于决定是否接话：名字/薄人格/兴趣、最多四条简短近期消息，以及最近 24 小时内
一个压缩摘要。不调用 embedding，不检索长期事实，不先加载完整人设与全部历史。
默认从核心人设首行取简短身份；可用 `decision_persona` 单独写薄人设。

`features/chat/judgement.py` 按估算控制到约 300 输入 token，输出上限 64 token，
使用短 JSON 表达回复/等待/跳过、目标、本轮是否需要深层记忆和复杂推理。实际以 usage
为准。明确 @/回复机器人可在本地直接进入回复，避免一次多余的判断请求。

决定回复后才加载完整核心人设、成长笔记与受限历史；问到过去事实/经历，或判断明确
需要时，才检索深层事实/事件。闲聊不默认加载全部长期信息。图片同样在决定回复之后
才下载与识别；跳过/Observe 不消耗这次识图费用。编辑、忘记与权限检查仍然约束发送。

正常回答由 `reply_max_tokens=300` 控制，指生成的 token，不等于 300 汉字；复杂思考
使用独立上限。一次生成可用内部断句标记表达最多三条自然短消息，总预算不倍增，
不按标点强制拆句。每条之间约 0.6～1.2 秒；有人接话或状态改变就停止剩余部分。
`reply_burst_enabled` 可关闭。每个分段有持久化发送状态，未知结果不补发，重启不续发
未发送部分；只有实际发出的内容进入聊天记忆。主动冲浪分享始终是一条。
到期后原文清空，事实可继续保留来源 ID、作者与时间等证据元信息。
批任务成功完成后清掉任务内的原文副本；失败最多重试三次。

每个频道使用独立 `discord:<guild-id>:<channel-id>` 范围。相同昵称、同一成员在不同群，
都不会自动共享记忆。初次接收新消息时可以恢复该频道的最近保留原文；机器人不会主动
抓取 Discord 旧历史。当前摘要按批生成，召回使用近期摘要，没有额外的跨月总结代理。

## 检索与可选语义召回

不配 embedding 也能运行。默认使用英文词与中文双字词匹配，加上当前说话人的少量
个人资料权重。当前检索候选限制为频道最近 1,000 条有效记录，适合先做测试版；
更大长期数据规模需要再加入可扩展全文/向量索引。

语义召回使用独立服务，并不是向 DeepSeek 对话端点发送 embedding 请求：

```dotenv
EMBEDDING_BASE_URL=http://127.0.0.1:11434/v1
EMBEDDING_MODEL=你部署的模型
# EMBEDDING_API_KEY=服务需要时填写
EMBEDDING_DAILY_REQUEST_LIMIT=300
EMBEDDING_MAX_REQUEST_CNY=0
```

Base URL 要包含服务要求的路径前缀；程序在后面追加 `/embeddings`。
外部 embedding 必须配置每次请求的保守人民币费用上界；免费本地服务才使用 0。
在 Memory 页启用 Semantic recall 后，后台逐步补齐旧记录向量；缺配置、额度用完或
服务失败就退回关键词。只比较同模型名、同维度向量。更换了实际模型权重时应使用不同
模型标识或离线重新构建向量，避免把不兼容空间当成同一模型。

## 查看、修正、忘记

网页 Memory 页选择服务器和频道，支持：

- 按成员 ID 过滤、分页、查看来源消息链接与原文。
- 批准候选，展开表单修正有效/候选记录。
- 勾选 Include memory history 查看替代、到期和已忘记的元信息。
- 忘记单条记录或一个成员在当前频道的全部保留信息。
- 导出该频道的记录与历史为 JSON；已忘记文本保持清空。

成员可以使用：

```text
/memory list
/memory remember text:我喜欢古典音乐
/memory correct memory_id:记录ID text:我现在更喜欢爵士乐
/memory forget
/memory forget memory_id:记录ID
```

前缀形式也可用，例如 `!memory remember 我喜欢古典音乐`。Slash 响应仅本人可见；
前缀响应出现在当前频道。成员只能查看/更正/删除自己的 profile；网页本机管理员
可以处理所选频道的共享事件与摘要。

更正保留替代关系。忘记会清空相应来源与派生文本、删除向量、清理任务副本、
使正在生成的回复失效，并留下防重放的元信息。删除一条记忆也会影响使用同一来源的
其他派生记录；操作前网页会说明这一点。忘记只作用于本地保留内容，不删除群里的原始
Discord 消息，也不能撤回已经发送给模型服务的请求或外部备份。

## 运行、备份与故障

`data/chat/chat.sqlite3` 保存决策/发送状态；`data/memory/memory.sqlite3` 保存来源、
记忆与任务；`data/ai/usage.sqlite3` 保存调用、金额与缓存统计；`data/ai/persona.sqlite3`
保存成长笔记、计数、来源与回退历史。均不进入发行包或 Git，自动更新会一同备份。
配置在 `config/guilds/<guild>/`；聊天/记忆保存相对全局默认值的差异，
原有音乐/欢迎配置仍保持独立快照语义。

备份前先停止机器人，复制 `config/` 与 `data/`；在线备份须使用 SQLite backup API，
不能仅复制正在写入的主数据库文件。不要同时启动多个机器人进程共用数据目录。
损坏的数据库会报错而不会被静默清空。AI 初始化失败时现有功能继续启动；
记忆不可用时群聊可退回当前短期上下文，关键词/向量故障在页面或日志中可见。

测试版可以用 `!update branch:chatbot` 跟进分支，或 `!update 提交SHA` 固定版本。
整套代码（包括记忆代码）一起更新，已有记忆数据库不替换、不重置。
更新器在停止机器人后使用 SQLite backup 备份 AI 数据到
`runtime/updates/<job-id>/data-backup/`，并在准备和应用时检查声明的记忆格式。
不兼容的格式需要先提供明确迁移方案，本次不会自动强制迁移。
回滚代码时保留当前数据，不自动用旧备份覆盖新记忆。首次使用前须先安装包含这个
更新器的版本；旧版 `!update` 只有 Release 功能。详见 [更新指南](releases.md)。

离线验证：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe main.py --check
.\.venv\Scripts\python.exe scripts/preview_dashboard.py
```

预览地址为 `http://127.0.0.1:8876/`，只用临时假服务器和临时数据，不连接 Discord、
不调用模型。真实验收应在测试频道依次确认：Observe 静默、主动接话频率、@ 回应、
真实缓存命中率/延迟、跨重启记忆、更正/忘记后不再引用旧内容、原有音乐与语音操作。
QQ/微信适配器、语音 AI 群聊、定时主动话题和任意命令执行不在本次实现范围。

## 自主联网与积极接话

在 Group chat 勾选 **Allow the bot to search the web when needed** 后，模型可以自行选择
`web_search` 与 `read_webpage`。这两个只读工具调用
[DeepSeek 官方 Search/Fetch 接口](https://api-docs.deepseek.com/guides/search/)，沿用当前 API Key。
时效信息、新闻、版本、价格和需要核实的资料适合搜索；日常闲聊、观点和个人记忆不必搜索。
模型会根据返回结果继续判断是否需要再搜或阅读页面，回答使用检索事实时应附来源链接。

默认单轮最多 3 次联网请求，每日由共享 ¥1 预算控制；Advanced 可加设次数上限。
搜索与网页读取按服务方的独立请求计费规则计算，不属于缓存 token 的免费复用。
工具请求同样计入本地全局请求额度，结果按频道短暂缓存 120 秒；失败会明确告诉模型，
不生成虚假的检索证据。网页文字视为外部资料，不会当作系统指令执行。工具只能读取
公开页面，不能访问本机文件、内网地址、凭据链接或运行命令。

选择 **Active** 后，`features/chat/participation.py` 的 `participation_plan()` 负责决定等待时间。
以测试配置基础间隔 8 秒为例：同一成员接着聊约 2 秒、问题约 4 秒、普通插话约 8 秒；
20 秒内有至少 6 条消息时，非追问间隔再乘 1.5。显式呼叫约等待 0.35 秒。
消息到达时即使还在间隔内，也会等待到期再判断一次，不需要成员重新 @ 或再发一条。
语义上是否接话仍由判断模型选择，Active 更倾向参与问题、观点、玩笑和追问。
只 @ 其他成员仍会本地跳过。Active 的直接呼叫频率上限为每成员每频道 30 秒 8 轮。

Balanced 保留原有固定间隔。两个模式都遵守频道允许列表、排除成员、安静时段、
每小时/24 小时自主发言额度和模型调用额度。普通接话不会在没有新消息时循环调用模型；
另行启用的兴趣冲浪只检查低频机会，遵守下面的额外约束。
工具定义在回复阶段保持稳定，当前时间、工具结果放在后部；工具模式与判断模式的
服务端缓存命中应分别看实际 usage，不假定二者共享全部缓存。

## 渐进人设与反馈提问

启用 **Gradually develop habits** 后，核心人设仍是管理员填写的原文，程序不自动修改。
每个频道另外保留六个可选成长槽位：说话方式、兴趣、幽默、聊天习惯、群文化、好奇心。
每次最多新增或修改一个槽位、80 字。资料包括允许频道的真人消息与实际成功获取的网页；
网页只能启发兴趣，不能授权修改身份、规则、权限或工具行为。

`features/persona/policy.py` 定义随累计消息数 n 下降的复盘频率：

```text
p(n) = 1/120 + (1/12 - 1/120) × exp(-n/600)
新消息门槛 = ceil(1/p(n))
最短复盘间隔 = 600 + 2100 × (1 - exp(-n/600)) 秒
```

初期约 12～13 条消息一次机会、至少约 10 分钟；逐渐降低到约 120 条、45 分钟。
不设每天两次的硬限制。重复消息不增加计数，网页也不算聊天数量；计数跨重启保留。
复盘可以选择不改，且不会因群里沉默而定时调用模型。

前 200 条要求至少两条来源和 0.8 置信度；磨合期要求三条、0.9；累计 1200 条后进入
稳定期，要求四条、0.95。候选还须经过单独的 `persona_audit` 审核：与核心一致、依据
充分、增量小且合理才保存。改身份、编造现实经历、极端/离谱跳变、注入规则不会作为
成长目标。模型审核并非绝对可靠，所以保留历史，并在网页按频道提供回退。

初期/磨合期可在自然回复中偶尔问一个与说话方式或话题兴趣有关的问题。至少有一批新
聊天且两次至少间隔 30 分钟；不会额外脱离对话发问。稳定期停止这类人设反馈提问。
源消息编辑/删除或成员被忘记会撤销相关笔记，清除相关历史原文，并使在途更新失效。
手动改核心身份后，旧核心对应的成长笔记不再参与提示词。

## 图片识别

启用 **Understand image attachments** 后，支持 Discord 附件中的 PNG/JPEG/GIF/WebP。
每条最多两张、每张最多 8 MiB、边长最多 8192 像素，只接受与当前频道匹配的 Discord
CDN 附件地址。机器人先限量下载附件并以内嵌图片发送给模型，避免模型端无法访问
Discord 签名链接；不跟随下载重定向，也不向 CDN 发送 Bot Token。纯图片消息也能触发判断。
图片先由 `deepseek-flash` 看一次，生成有
不确定性标记的文字观察，再交给群聊判断与回复；同一消息短暂缓存，避免重复识图。

原始图片不落盘，签名地址不写入历史/记忆/人设。启用记忆时只保留带来源的文字观察；
它不是成员自述，不能单凭图片推断个人事实。识别失败不猜测内容。编辑/删除消息会
使缓存失效。这里只支持图片附件，普通外部图片链接、视频和语音不自动下载识别。
按[官方图像接口](https://api-docs.deepseek.com/guides/vision/)沿用现有 Key 和模型。

## 偶尔按兴趣冲浪

勾选 **Occasionally browse for interests**，且群聊为 Participate、联网开关已开时，后台
每分钟只做一次本地资格检查，不符合条件时不调用模型。实例启动后先观察一小时；
此频道需要积累 20 条新真人消息，最后真人消息和机器人发言均已过去至少两分钟，
且真人最近半小时内聊过。安静时段、正在生成回复或最近消息在点名/回复别人时跳过。

全实例每天最多两次冲浪尝试，间隔至少六小时，最多分享一条，重启不重置次数。
每次最多一个通用兴趣查询，不把群友身份或原始聊天带进搜索词。查询依据核心人设、
配置兴趣与已形成的兴趣/好奇心笔记。模型再结合结果和少量当前聊天决定是否值得分享；
无好内容则保持安静。分享必须有真实来源链接，30 天内的相同链接/标题不重复分享。
中途新消息、配置变化、权限变化或跨日会取消。未知发送结果按已占用名额处理，不补发。

冲浪规划、搜索和筛选均计入共享 ¥1 预算，同时受其中 ¥0.10 子预算约束；总余额低于
¥0.20 时保留给正常聊天。成功查到的材料也可以作为渐进人设的兴趣参考，不改变核心。
状态/去重保存在 `data/ai/surfing.sqlite3`，更新器一同备份。

## 按需深度思考

**Thinking mode** 可选 Automatic 或 Fast replies only。普通闲聊和查事实默认不思考；
证明、推导、算法、排错等复杂问题可用 low，明确要求深度思考/认真分析可用 high。
无 @ 的复杂度也可以由既有接话判断提供，不额外加一次路由调用。余额低于 ¥0.10 时
退回快速模式。low 单请求输出上限 1536 token，high 为 2048，包含思考和最终回答；
思考 token 已包含在 API completion_tokens 内，按输出单价计费，不重复累加。

按[官方思考接口](https://api-docs.deepseek.com/guides/thinking_mode/)传入 thinking 和
reasoning_effort。思考中连续调用工具需要原样回传该轮 reasoning_content；只在该回复
的内存里保留，不写入群聊、人设、记忆或日志。上下文/权限检查仍在各工具步骤和发送前执行。
若达到思考输出上限，只允许一次快速模式降级；已消耗的思考费用仍结算。
