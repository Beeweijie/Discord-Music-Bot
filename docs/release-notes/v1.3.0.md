# v1.3.0

Each Discord server now has one player and one shared queue. Switching voice
channels no longer creates another queue or leaves playback controls attached
to the previous channel.

## Changes

- `/join` moves the bot while keeping the current track, queue, position, volume,
  repeat mode and pause state. Moving the bot in Discord keeps the same player.
- Playback controls require the member to share the bot's current voice channel.
  When disconnected, `/resume` can restore the server queue in any voice channel.
- The dashboard shows one queue per server, with its current or last voice channel.
- Voice interruptions allow up to 60 seconds for SDK recovery. A failed recovery
  saves the current track and queue for explicit `/resume`.
- Unchanged Discord player panels no longer trigger repeated message edits.
- Background task failures, voice recovery and shutdown have more detailed logs.

## Upgrade

Back up `config/`, `data/`, `.env` and local music before upgrading. A successful
update does not automatically rejoin voice; use `/resume` afterward.

Queue storage changes from `data/queues/<guild>/<voice>.json` to
`data/queues/<guild>/queue.json`. On first restore, the latest channel snapshot
supplies settings, location and the first tracks. Other channel queues append
with duplicates removed. Existing tracks are kept even when the merged queue
exceeds the current limit; new additions still respect that limit. Original
channel files remain on disk as backups. Stop writes an empty server snapshot
so those original queues cannot reappear on the next restart.
If an update rolls back and the older bot subsequently changes its channel
snapshots, the next upgrade migrates those newer snapshots again.

Custom management clients must use the server ID as `session_id`. The controls
endpoint is now `/api/v1/sessions/<guild_id>/controls`, and session keys returned
by the API are server IDs. Reload the dashboard after updating.

Older releases cannot read the new server queue format. For a manual downgrade,
restore the pre-upgrade `data/` backup along with the older application files;
the retained channel files do not include playback changes made in v1.3.0.

Install both the ZIP and its SHA-256 asset when publishing this release; `!update`
requires both. Users upgrading from a Linux installation through v1.2.0 may
still need the [one-time Linux updater repair](../releases.md#linux-updates-failing-before-code-replacement).
