# v1.4.0

Optional local Chinese voice controls are now available. Say "喵酱喵酱", wait for the spoken acknowledgement, then give a music command. You can also say the wake phrase and command together.

## Changes

- Local speech recognition with SenseVoiceSmall / FunASR and an optional phonetic wake detector. Audio is processed in memory; recordings and ordinary conversation transcripts are not saved.
- Fixed replies in a synthesized Chinese Klee character voice. Replies briefly lower the music volume and do not advance a paused track. Model and voice attribution are documented in the [voice reply guide](https://github.com/Beeweijie/Discord-Music-Bot/blob/v1.4.0/docs/voice-replies.md).
- Pronunciation-based song matching, such as "与爱" to "雨爱", using the queue, history, personal favorites and saved playlists. Ambiguous searches offer up to three candidates.
- Voice requests beginning with "播放" add the requested song to the front and play it immediately. Requests beginning with "加入" append to the queue without interrupting playback or starting an idle player. "播放歌单" continues the existing queue.
- New `!playskip <song or URL>` and `/playskip` commands, with single-track, playlist and autocomplete support. `playtop` still inserts at the front without interrupting the current track. Failed searches do not skip playback, and the remaining queue is preserved.
- Say "闭嘴", "取消" or "安静" to end your current listening session, cancel candidate selection and stop the spoken reply while music continues. Text fallbacks are `!voice quiet` and `/voice quiet`.
- A new wake phrase exits the previous candidate menu and cancels the previous search. Each wake allows at most one retry prompt; listening expires silently. Wake phrases, cancellation and follow-up commands remain available during replies and searches.
- Opt-in diagnostics with `!voice test` or `/voice test`: up to three transcriptions from the requesting member over 30 seconds. Prefix-command results appear in the channel; slash-command results are visible only to the requester.

## Installation and upgrade

Existing music features work after a normal upgrade. Voice controls are disabled by default. The existing `!update` command accepts this release package; use `/resume` afterward to restore a saved queue.

To enable voice controls, run this command from the project root:

```text
python scripts/install_voice.py
```

The helper selects the bot's active update environment or `.venv`. Follow the [README](https://github.com/Beeweijie/Discord-Music-Bot/blob/v1.4.0/README.md) to download the SenseVoice model separately; installing the phonetic wake model is also recommended. Set `VOICE_COMMANDS_ENABLED=true` and `VOICE_ASR_LANGUAGE=zh` in `.env`, restart, and use `/join` to connect the bot to your voice channel. Large recognition models are not included in the release.

Linux also requires the system Opus library. On Debian, Ubuntu or Raspberry Pi OS, install it with `sudo apt-get install libopus0`. Voice startup checks the native codec and reports missing dependencies.

When upgrading with an older updater, run the helper again after upgrading if voice controls were already enabled in a custom installation, then restart. Starting with v1.4.0, update preparation installs optional dependencies when voice controls are enabled. Existing settings, user data, models and saved queues remain covered by the current preservation and rollback mechanisms.

## Validation and known limitations

The release workflow installs optional dependencies and runs the full suite on Linux and Windows. Linux also verifies operation with base dependencies only. Coverage includes queue insertion and immediate playback, paused playback, candidate cancellation, cancellation of slow searches, bounded retries, same-channel permissions, archive manifests, updates and rollback.

Before publishing, 246 tests passed on Linux with three platform-specific skips and on Windows with two platform-specific skips. The final GitHub Actions workflow passed all 247 tests on Windows and the Linux suite with three platform-specific skips. The original v1.3.0 updater successfully extracted the new ZIP, all five embedded replies matched the original audio byte for byte, and both model download links returned successfully. The published ZIP was downloaded and checked against both the SHA-256 file and GitHub's asset digest.

Live testing successfully triggered wake-up, skipped tracks and played Rainie Yang's "雨爱". Incorrect transcriptions and misrecognized song-version suffixes still occurred. Headphones, artist names and candidate selection help resolve ambiguity; recognition accuracy still needs validation in actual use.
