# 喵酱语音回复

喊“喵酱喵酱”后，会用合成的可莉中文角色音色回答“我在喵”。回复结束后，等待本人的下一段音乐指令，等待时间为 8 秒。可以说“下一首歌”“播放周杰伦的晴天”“暂停播放”“继续播放”。每次唤醒最多说一次“没听清喵，请再说一次”，不会因听错不断延长监听；再次听不懂或超时后安静退出。也兼容一次说完唤醒词和指令。

播歌时回复会与音乐混音，并短暂降低音乐音量；回复结束后恢复原音量。已暂停的音乐在回复期间不读取音乐帧，回复结束后仍保持暂停。空闲时用同一语音连接播放短回复。回复和音乐控制共用原有控制、播放锁，避免抢占正在准备的歌曲。回复期间继续接收声音，标记重叠片段：保留重新唤醒、取消及已唤醒后的明确音乐指令，忽略普通回复回声。

说“闭嘴”“安静”“取消”可停止当前回复、结束本人的监听和候选选择，不停止音乐；同频道成员还可用 `!voice quiet` 或 `/voice quiet` 文字兜底。搜索和指令任务独立于识别循环，新唤醒或取消会撤销该成员旧任务，旧搜索即使稍后返回也不会执行。重新喊“喵酱喵酱”可退出候选菜单再说新指令。“播放歌单／列表／队列”播放当前队列，不搜索名为“歌单”的视频。

五句固定回复（包括候选选择提示）存放在 `bot_app/features/music/media/replies/`，48 kHz、16-bit、双声道 WAV，总计约 1.3 MiB。运行时只播放本地文件，无需 TTS 网络服务，也不会在树莓派常驻加载语音合成模型。

为兼容旧更新器的文件白名单，Release ZIP 将同一组固定音频无损压缩存放在 `voice_assets.py`，不包含原始 WAV 或根目录 `requirements-voice.txt`。源码仓库保留 WAV 和依赖清单；可用 `python scripts/build_voice_assets.py` 重新生成嵌入资源。运行时优先读取源码 WAV，否则解码内置资源，音频内容相同。语音依赖安装入口为 `python scripts/install_voice.py`。

语音“播放雨爱”会使用 `playskip`，把新歌放到队首并跳过当前曲目；“加入雨爱吧”只加入队尾。空闲时的“加入”不会自动开播。歌名通过 pypinyin 的不带声调拼音匹配常用曲目和当前服务器的音乐上下文，支持“与爱”→“雨爱”等同音联想。随后检索多个 YouTube 音乐候选，按歌名、歌手、官方频道和音乐标记排序；无法确定时等待点歌者在 30 秒内用“第一个”等口令选择，其他成员不能替他选择。此过程不限定游戏音乐。

音色来源：使用 sherpa-onnx 的 [VITS 多角色模型](https://huggingface.co/csukuangfj/vits-zh-hf-eula)，按其原始 [804 角色配置](https://huggingface.co/spaces/zomehwh/vits-models-genshin-bh3/blob/main/config/config.json) 选择中文“可莉”（speaker id 103）生成。模型虽以 eula 命名，支持 804 个 speaker；本次选用的是可莉条目。该音色为模型合成，非游戏官方录音。生成参数 `sid=103`、`speed=1.05`，生成后转换为 Discord PCM。没有下载或执行原模型仓库的 Python 源码。

音频识别同时增加 250 ms 前置静音。在重现的点歌/继续口令中，这能保留原先被省略的第一个“喵”。额外兼容用户本人测试中出现的“将喵将下一首歌”和“将喵降下一首歌吧”；只有其后的完整音乐命令能触发执行，单次叫一个名字不会执行命令。
